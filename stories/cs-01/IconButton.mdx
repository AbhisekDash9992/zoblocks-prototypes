## Types and states

Type describes the visual family. State describes interaction. Committed criteria determine the contextual Type; opening an editor or hovering a button does not mean applied.

Ghost Default/Hover/Focused uses `icon/primary`; Hover and Focused use `bg/primary-hover`. Ghost Disabled uses `icon/disabled` on transparent. Ghost-primary Default/Hover/Focused uses `icon/brand-primary`; Hover and Focused use `bg/brand-primary-hover`. Ghost-primary Disabled requires `icon/brand-disabled` on transparent. Its exact number is unavailable, so its icon color specimen is withheld rather than painted generic gray or a guessed brand color. Native disabled behavior is still testable; this is not visual acceptance.

## Usage guidance

- Use a recognizable icon for a compact action, with a specific accessible name such as “Filter” or “Remove Sort.”
- Use Ghost-primary when matching criteria are committed. Provide contextual text or a summary so applied status is understandable beyond color.
- Prefer a text button when the action is unfamiliar or needs explanation. A tooltip does not replace a visible label in those situations.
- Do not use this pilot to infer unsupported Sizes, Shapes, Types, production semantics or clinical behavior.

## Accessibility

The reference reuses a native button. The accessible label remains present when tooltips are disabled; SVG and slot are decorative. Native disabled buttons cannot activate and are skipped by sequential keyboard navigation.

Use Tab / Shift+Tab to move focus, Enter / Space to activate, and Escape while the trigger is focused to dismiss its tooltip. The existing tooltip opens on hover or focus and dismisses on pointer leave, blur, click, activation keys or scroll. A hover-only tooltip does not receive Escape when keyboard focus is elsewhere; move the pointer away to dismiss it. It uses `role="tooltip"` and an open-time description relationship. Disabled controls cannot receive ordinary keyboard focus; their tooltip must never contain essential instructions.

The reused tooltip is pointer-inert and does not support hovering its content. Description preservation and assistive-technology behavior need human review. This batch does not modify the tooltip implementation or claim full accessibility conformance.

Tooltip visuals, including Remove Sort, are pending their own component specification. Existing hover/focus/dismissal behavior and the accessible name “Remove Sort” are retained.

A 24px visual control does not certify touch-target suitability. Ghost keyboard focus uses the supplied solid white 2px inner shadow and neutral hsl(216 15% 34%) 4px outer shadow, with bg/primary-hover even without hover. The inherited outline is suppressed to avoid a third ring. Forced-colors mode uses a solid system-color Highlight outline because shadows can be suppressed by the browser. Disabled controls have no hover/focus background or ring.

Ghost-primary uses the directed layered behavior with white 2px and a provisional #155DFC outer layer adapted from the inspected **Primary** bg/brand-solid reference. The exact Ghost-primary outer binding is not independently verified. The Ghost diagram depicts its neutral ring, not Primary’s brand ring. External numbered leaders connect to precise feature endpoints; dashed/dotted slot and glyph-box guides are construction only. Keyboard tests and human visual review are separate evidence.
