# Tabs

CS-05 · Oxygen Light · Interactive design reference · Local review

## Overview

Tabs switch among related content sections within one context, displaying one panel at a time. Use them when the sections are peers and users benefit from keeping their place. Five parent styles share four atom Types and three inspected visual States, giving **12 standalone atom specimens**.

**Tabs** owns selection, focus, keyboard navigation and panel relationships. **TabAtom** is a separately reusable presentational control; its selected appearance is supplied by its parent. This Storybook explains design and demonstrates behavior. Production developers independently choose component APIs, architecture and integrations; these reference renderers are not production-certified contracts.

## Component composition

<Composition />

The nested Badge is an actual Figma **component instance**, not text and a border inferred to look like one. CS-03 and CS-05 now consume the **same portable reference Badge implementation**. Standalone CS-03 Medium stays 24px minimum height with 4px / 10px padding; Tabs-context Medium is 20px with 2px / 10px padding. It stays **Medium**, never Small. The context overrides geometry only and retains the verified tinted #F2F3F5 fill and 1px inside #D1D5DC edge. In Tabs, Close and Icon start are off, with no nested button or independent tab stop.

Lucide is the existing SVG rendering mechanism for replaceable artwork. No Icon Button is used, and this composition needs no new shared Icon primitive. Decorative SVGs are hidden from assistive technology, not independently focusable and pass pointer interaction to the parent tab. Component alias bindings and original artwork remain unverified.

## Usage guidance

<Canvas of={TabsStories.UsageExamples} />

Choose Simple text, Leading icons, Count Badges, Trailing icons, Longer labels or Narrow overflow. One live example changes its configuration; it uses the same Tabs component and minimal, section-specific content. Long labels stay intact in a single scrollable row. No extra tab navigation menu or truncation rule is invented.

- Use tabs for related peer sections such as an enterprise workspace overview, properties, activity and files. A future Data Grid may appear inside a panel when that grouping matches the content model; no Data Grid integration is implemented here.
- Use links for destinations and routing. Use appropriate form controls for choices or filters. Do not turn filter chips, row actions or unrelated workflows into tabs just because they share a visual shape.
- Keep labels specific and stable. Counts supplement the label; trailing icons do not imply a close, menu or second action. Avoid using icons alone to convey essential information.
- The local overflow decision keeps all four tabs reachable by horizontal scrolling and keyboard focus. Wrapping, responsive dropdowns, deletion, persistence and dynamic item policies need separate design decisions.

## Accessibility

This reference follows the [WAI-ARIA APG Tabs pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/), using manual activation as an approved local decision. The following describes the implemented horizontal reference, not an assistive-technology certification.
