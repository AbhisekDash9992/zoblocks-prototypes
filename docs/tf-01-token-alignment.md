## Safe future substitution boundary

Opt in only the separately approved reference component, preserve Light appearance first, and compare computed styles before/after. Do not add a mode to the existing global `.dg-page` wrapper: that could affect unrelated consumers. Preserve native behavior and clinical/context semantics. Dark component styling remains unverified even though the foundation's Dark aliases are verified.

`stories/docs-reference.css` and each pilot's local chrome repeat neutral colors, font stacks, spacing and radii. Documentation chrome may eventually use the foundation in its own scope, but that migration is outside TF-01. Token availability does not authorize replacing every matching literal. No CS-04 Button is implemented.

## Native export reconciliation (22 October)

The portable foundation now contains 124 known primitives: 121 preserved scale values and native-verified white, black and transparent. Black aliases gray/950 (#030712); transparent is literal #000000 at 0% alpha. White-dependent semantics resolve directly, with 50% text and 80% icon disabled alpha retained. The two brand scales remain grounded in the earlier register because the native export omits them.

Exactly two older semantic mappings are superseded: Light border/brand-primary is blue/600 (#155DFC), while Dark stays blue/500; Dark icon/danger-primary is red/500 (#FB2C36), while Light stays red/700. These foundation corrections do not authorize substituting accepted pilot colors or focus layers. A future component mapping must use the correct role and mode; matching an old literal is insufficient.

The native source spelling bg/success-disbaled is normalized to the existing public bg/success-disabled / --ox-bg-success-disabled; aliases remain green/500 in Light and green/800 in Dark. Catalog metadata and validation preserve this traceability without publishing native IDs or source JSON. Label, tracking-unit, advanced text-setting, hidden-shadow-layer, gradient-direction and component-focus evidence gaps remain unchanged.
